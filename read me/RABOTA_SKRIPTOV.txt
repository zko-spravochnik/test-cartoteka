ВАЖНО ПРО СЕКРЕТЫ. В этом файле НЕТ ни одного настоящего пароля, токена или
номера чата. Они лежат только в вашем скрытом файле secrets.txt (вне папки

Как читать этот файл: сначала общая картина (раздел 1), потом — что за файл
отвечает (разделы 2–5), потом — сквозные сценарии «что нажать и что будет»

===============================================================================
1. ОБЩАЯ КАРТИНА: КТО С КЕМ РАЗГОВАРИВАЕТ
===============================================================================
Представьте почту с четырьмя отделениями.

1) САЙТ (витрина). Файлы index.html, style.css, script.js и другие. Лежат на
   GitHub Pages. Житель открывает сайт на телефоне. Сайт показывает справочник и
   принимает заявки. Своего сервера у сайта нет.

2) GOOGLE-ТАБЛИЦА + СКРИПТ-ШЛЮЗ (приёмная). Заявка жителя уходит в Google
   Таблицу, где ей присваивается ID и статус «Новая». Тут же шлюз пишет вам в
   Telegram: «пришла заявка».

3) ЛОКАЛЬНЫЙ СЕРВЕР на вашем телефоне (cartoteka_server.py в Pydroid 3). Это
   ваш рабочий кабинет: он проверяет Код входа, читает secrets.txt, дописывает
   одобренные строки в базы, отправляет изменения на GitHub и шлёт рапорт в
   Telegram. Пульт администратора без запущенного сервера не открывается.

4) GITHUB (склад). Там лежат боевой сайт (zko-spravochnik/cartoteka) и
   тестовый сайт (zko-spravochnik/test-cartoteka). Всё, что попало на GitHub,
   через несколько минут видят жители.

Путь заявки целиком:
   Житель заполняет анкету → заявка уходит в Google Таблицу (ID, «Новая») →
   вам приходит сообщение в Telegram → вы открываете пульт, «Очередь заявок» →
   нажимаете «Одобрить» → сервер дописывает строку «$» в файл села → кнопка
   «В GitHub» отправляет файл на склад → жители видят карточку.

Правило «две среды»: адрес localhost / с портом / с test-cartoteka = ТЕСТ,
любой другой = БОЙ. Код определяет это сам. Метка «[ТЕСТ]» в заголовке вкладки
говорит, что вы в песочнице. Релиз v1.0.0.0 выкладывается в БОЙ.

-------------------------------------------------------------------------------
2.1. cartoteka_server.py — ЛОКАЛЬНЫЙ СЕРВЕР (главный рабочий инструмент)
-------------------------------------------------------------------------------
ГДЕ ЛЕЖИТ: в корне папки проекта, рядом с index.html.
НА GITHUB НЕ УХОДИТ (загрузчик его пропускает намеренно).
ЗАЧЕМ: пульт администратора на сайте умеет только показывать кнопки. Все
«опасные» действия (писать в файлы, ходить на GitHub, читать secrets.txt)
делает этот сервер. Сайт сам файлы на телефоне изменить не может.

КАК ЗАПУСТИТЬ (Pydroid 3):
  1. Откройте Pydroid 3 → меню «Папка» → откройте файл cartoteka_server.py.
  2. Нажмите жёлтую кнопку ▶ (Run). В терминале появится строка:
     «КАРТОТЕКА: сервер запущен, откройте http://localhost:1090».
  3. Откройте Chrome и введите http://localhost:1090.
  Если порт 1090 занят — запустите с другим номером: в терминале Pydroid
  введите  python cartoteka_server.py 1108  (можно 1110 или 1112).
  Терминал и Pydroid НЕ закрывайте и не смахивайте: пока он открыт, сервер жив.

ЧТО ДЕЛАЕТ (по порядку «ручек»):
  /__ping        — «сервер жив?». Пульт спрашивает это первым. Нет ответа →
                    на экране «Запустите сервер».
  /__auth        — проверка «Кода входа в админку». Хранится только отпечаток
                    (PBKDF2-SHA256 с солью) в скрытом файле .admin_auth.json.
                    5 неверных попыток подряд → пауза 60 секунд.
  /__unlock      — проверка «Мастер-пароля изменений». Выдаёт сессию на
                    10 минут. Отпечаток лежит в .admin_master.json.
  /__lock        — досрочно гасит сессию мастера («Закрыть», «Забыть
                    устройство»).
  /__secrets     — читает ваш secrets.txt по пути, который вы вписали в окно.
                    Значения кладёт ТОЛЬКО в оперативную память сервера
                    (SECRETS_MEM). Выключили сервер — память очищена.
  /__append      — дописать строку в базу села (NEW), заменить строку (EDIT),
                    удалить плашку чата (DELETE чата). Перед записью делает
                    копию в папке backups_local (хранит последние 20).
  /__github_push — то же самое, но прямо на GitHub: читает файл села, вносит
                    правку, отправляет, при конфликте повторяет до 3 раз, затем
                    шлёт вам рапорт в Telegram.
  /__push_gas    — «кремовая кнопка»: отправляет код шлюза в Google.
  /__vipcheck, /__autopilot — сверка VIP и «автопилот коммерции».

НОВОЕ В v1.0.0.0 — МИГРАЦИЯ КАТЕГОРИЙ В ПРАВКАХ (EDIT):
  Если в заявке на правку вы меняете категорию (например «Продукты» →
  «Онлайн-магазины/ПВЗ»), то у карточки меняется и ID (было 1107, стало 1705).
  Раньше строка просто заменялась «на месте». Теперь сервер:
   а) находит СТАРУЮ строку по старому ID (по полю «оригинал»);
   б) проверяет, что старая строка в файле совпадает с оригиналом заявки;
   в) проверяет, что новый ID свободен и что Г1 соответствует категории из Г2
      и маске Г17 (плитка C и подкатегория T1);
   г) УДАЛЯЕТ старую строку из прежней секции файла;
   д) ВСТАВЛЯЕТ новую строку в новую секцию на своё место по возрастанию ID;
   е) пишет в терминал Pydroid строку «[МИГРАЦИЯ] … 1107 → 1705 · Магазины —
      Продукты → Магазины — Онлайн-магазины/ПВЗ»;
   ж) пересчитывает счётчики села.
  Это одинаково работает и для файла на телефоне (кнопка «В файл + Буфер»), и
  для GitHub (кнопка «В GitHub»). В рапорте Telegram будет пометка «перенесена
  запись (миграция …)».
  Возможные отказы: «link_mismatch» (Г1 не совпал с категорией Г2),
  «idclash» (новый ID занят), «mismatch» (старая строка в файле не такая, как в
  заявке), «no_id» (старой строки нет). Каждый показывается по-русски.

ЧТО ДОЛЖНО ПРОИЗОЙТИ НА ВЫХОДЕ:
  В терминале Pydroid — строка «сервер запущен». В пульте — бейдж
  «🔒 Только чтение» (после Кода входа) или «🔓 Изменения разрешены» (после
  Мастер-пароля).

2.2. github_uploader.py — ЗАГРУЗЧИК САЙТА НА GITHUB (деплой)
-------------------------------------------------------------------------------
ГДЕ ЛЕЖИТ: в корне папки проекта (имя папки может быть любым).
ЗАЧЕМ: выложить обновлённый сайт на GitHub Pages, чтобы его увидели жители.
Отправляет ТОЛЬКО витрину сайта и ТОЛЬКО изменённые файлы, одним коммитом.

ЧТО НЕ ЗАГРУЖАЕТ (намеренно): все .py, .gs, geo_prev_directory_archive.json,
«google ссылка.txt», secrets*.txt, .admin_auth.json, .admin_master.json,
google_service_account.json, google_sync.json. Если находит в файлах витрины
шаблон токена GitHub или Telegram — ОСТАНАВЛИВАЕТСЯ и ничего не отправляет.

КАК ОНО ПОНИМАЕТ, ЧТО ИЗМЕНИЛОСЬ: считает md5 каждого файла, сравнивает с
памятью (.uploader_state.json) и ещё раз сверяет с тем, что реально лежит на
GitHub. Лишнего не уйдёт.

КЛЮЧИ ЗАПУСКА:
  python github_uploader.py          — обычная заливка;
  python github_uploader.py --dry    — ничего не отправлять, только показать
                                       список «что изменилось»;
  python github_uploader.py --force  — не верить памяти, сверить всё с GitHub.

ЧТО ОН СПРОСИТ: «1 — test-cartoteka, 2 — cartoteka». Для релиза вводите 2.
Токен GitHub берётся из вашей среды/ввода по тем же правилам, что и раньше
(в чат и в файлы проекта не вписывается).

ЧТО ДОЛЖНО ПРОИЗОЙТИ НА ВЫХОДЕ: в терминале — список отправленных файлов и
короткий хеш коммита. Через 1–10 минут (кэш GitHub Pages) сайт обновится; на
телефонах появится окно «Обновить сейчас».

2.3. google_code_pusher.py — «КРЕМОВАЯ КНОПКА» (обновление шлюза в Google)
-------------------------------------------------------------------------------
ГДЕ ЛЕЖИТ: в корне проекта. ВСЕГДА входит в ZIP-архив.
ЗАЧЕМ: код шлюза (google_apps_script_webhook.gs) слишком длинный для буфера
телефона. Заглушка в окне Apps Script короткая, а настоящий код живёт в ячейке

КАК РАБОТАЕТ: отправляет POST (action=pushCode, Мастер-пароль) на «Вебхук
Google Таблицы» (адрес, оканчивающийся на /exec). Шлюз сверяет MASTER_CODE и

КАК ЗАПУСКАТЬ: обычно вы просто нажимаете кремовую кнопку «Обновить облачный

этот скрипт сам. Автономно: python google_code_pusher.py.
НА ВЫХОДЕ: сообщение «передано, знаков: N». После этого в Apps Script один раз
сделайте «Начать развертывание → Управление развертываниями → Изменить →
Новая версия».
КОГДА НУЖНО: после каждого обновления файла google_apps_script_webhook.gs
(в релизе v1.0.0.0 он обновлён — комментарии в Telegram и миграция ID).

2.4. build_counts.py — ПЕРЕСЧЁТ СЧЁТЧИКОВ СЁЛ
-------------------------------------------------------------------------------
ГДЕ ЛЕЖИТ: в корне проекта. Запуск: python build_counts.py (из корня проекта).
ЗАЧЕМ: на экране района у каждого села есть две цифры [бизнес][жители]. Чтобы
не скачивать все 165 баз, цифры берутся из лёгкого индекса counts в config.json
и test_config.json. Этот скрипт открывает все 165 файлов, считает строки и
записывает индекс заново.
ЧТО СЧИТАЕТ: карточки бизнеса (Г2 ≠ «ЖИТЕЛИ») и жителей (Г2 = «ЖИТЕЛИ»).
НЕ считает: комментарии «#», строки не из 20 граф, строки-чаты (wa/tg) и строки
в карантине (любой маркер, кроме «$»).
КОГДА ЗАПУСКАТЬ: после ручных правок баз, перед деплоем. При обычной работе
индекс обновляется сам (при одобрении заявки и миграции).
НА ВЫХОДЕ: сообщение о числе обновлённых сёл и файлы config.json/test_config.json
с новым полем counts.

3.1. google_apps_script_webhook.gs — ШЛЮЗ ПРИЁМА ЗАЯВОК (Google Apps Script)
-------------------------------------------------------------------------------
ГДЕ ЖИВЁТ: на сайте Google в вашей Таблице («Baiterek_Ochered_2026»), в
Расширения → Apps Script. В архиве — файл-исходник (на сайт не загружается).
В Apps Script стоит короткая заглушка-приёмник (shablony_сейф/
priemnik_apps_script.gs), а настоящий код хранится в ячейке Код!A1 (раздел 2.3).
ЗАЧЕМ: принимает заявки со всех телефонов, присваивает ID (под блокировкой, без
пересечений), ведёт листы «Район_Село», хранит статусы, отвечает пульту и шлёт
Telegram-уведомления.
ГЛАВНЫЕ ДЕЙСТВИЯ: submit (новая заявка), list (очередь для пульта),
setStatus (одобрить/внесена/отклонить), updateRow (исправление опечаток),
reid (пересчёт ID), setTelegram / testTelegram, alarm (вход с чужого
устройства), pushCode (приём нового кода шлюза).
ЗАЩИТА: ADMIN_CODE открывает чтение; изменения требуют ещё и MASTER_CODE.
Оба лежат только в Свойствах скрипта.

НОВОЕ В v1.0.0.0:
  • updateRow разрешает менять ID ТОЛЬКО у заявок EDIT — это нужно для
    миграции категории (ID вместе с категорией). Для NEW смена ID по-прежнему
    запрещена.
  • Во ВСЕХ уведомлениях Telegram внизу появился «💬 Комментарий».

После обновления: кремовая кнопка → «Новая версия» развёртывания. Проверка:
откройте ссылку /exec в браузере — вернётся {"ok":true,"service":
"cartoteka-intake","version":"v1.0.0.0"}.

3.2. TELEGRAM-БОТ «КАРТОТЕКА ОПОВЕЩЕНИЯ» (@zko_cartoteka_bot)
-------------------------------------------------------------------------------
ГДЕ ЖИВЁТ: у Telegram. Токен бота и ID вашего чата хранятся в Свойствах скрипта
Google и в памяти сервера; в файлы сайта не попадают.
ЗАЧЕМ: говорит вам «пришла заявка», «ссылка сброшена», «запись внесена на

ЧТО ДОЛЖНО БЫТЬ СДЕЛАНО ОДИН РАЗ: нажать /start у бота; считать secrets.txt

КАКИЕ СООБЩЕНИЯ ПРИХОДЯТ (v1.0.0.0, у каждого внизу строка «💬 Комментарий»):
  • 🆕 Новая анкета — бизнес или житель: район, село, вид, ID, название/ФИО,
    телефоны, файл. Комментарий — примечание, как его написал человек (для
    жителя — Г5, если нет другого).
  • ✏️ Правка карточки — то же + комментарий, который посетитель написал в
    окне «Ошибка». Текст приходит БЕЗ ИЗМЕНЕНИЙ, например «Перевести в онлайн
    магазины..» придёт ровно так.
  • 🗑 Запрос на удаление — комментарий: причина (владелец против, переехал,
    закрылся, дубликат или ваш свободный текст).
  • 🆕/✏️/🗑 ссылка на чат (WhatsApp/Telegram) — цветная карточка чата: вид,
    индекс, название, описание, ссылка + комментарий.
  • ⚠️ Ссылка на чат сброшена — приходит на 1-ю и 3-ю жалобу жителей;
    комментарий «Ссылка сброшена».
  • ✅ Рапорт синхронизации — его шлёт ЛОКАЛЬНЫЙ СЕРВЕР после кнопки «В GitHub»
    (репозиторий, село, действие и ID, короткий хеш коммита, время).
  • 🚨 Тревога — «i» зажата на чужом устройстве без вашего сервера.
Если Telegram молчит — раздел 8.

4. БАЗЫ JSON И СЛУЖЕБНЫЕ ТЕКСТОВЫЕ ФАЙЛЫ (данные, а не код)
===============================================================================
Все лежат в корне проекта и редактируются обычным текстовым редактором
(осторожно: запятые и кавычки JSON не терпят ошибок).

-------------------------------------------------------------------------------
4.1. config.json и test_config.json — НАСТРОЙКИ СРЕД
-------------------------------------------------------------------------------
config.json — БОЕВОЙ (репозиторий cartoteka). test_config.json — ТЕСТОВЫЙ
(репозиторий test-cartoteka). Сайт сам выбирает нужный.
Что внутри: версия (appVersion, schemaVersion), список сёл и путь каждой базы
(villages / files), районы, ссылка веб-хука Google (intakeWebhookUrl), ссылка
для QR (qrShareUrl), имя репозитория и ветка, правила маршрутов,
счётчики сёл (counts), dbEpoch и updateCritical.
  • dbEpoch — «метка эпохи данных». Если её поменять, у ВСЕХ жителей сбросится
    память баз и они скачают всё заново. В релизе: 2026-10-31-v1000-cache-reset.
  • updateCritical=true — окно «Обновить сейчас» без кнопки «Позже».
Секретов (токены, пароли) здесь НЕТ и быть не должно: файлы публикуются.

-------------------------------------------------------------------------------
4.2. kazakhstan_geo.json — ГЕОГРАФИЯ
-------------------------------------------------------------------------------
Области, районы, села, КАТО, почтовые индексы, коды АТС и пути баз. Код АТС
района форма читает ТОЛЬКО отсюда (короткий городской номер до 7 цифр
получает код района автоматически). Новое село = пустой файл базы + строка в
config/test_config (villages и files) + строка здесь.

-------------------------------------------------------------------------------
4.3. languages.json — ВСЕ ТЕКСТЫ САЙТА
-------------------------------------------------------------------------------
Блоки «ru» и «kz» с одинаковыми ключами (паритет обязателен). Любую надпись на
кнопке или в окне меняют здесь, а не в коде. Названия районов — geoDistricts.
Ошибки очереди — ключи qe_… (в релизе добавлен qe_link_mismatch).

-------------------------------------------------------------------------------
4.4. categories.json — КАТАЛОГ 9×9 И ЦВЕТА
-------------------------------------------------------------------------------
Главные плитки (superTiles), подкатегории (subTiles['C'], номер sub = третья
цифра ID), плитки 3-го уровня (tiles, t2 = 0..9), цвет (hue: red, orange,
green, sky, blue, violet). Названия папок в базе (Г2) берутся ОТСЮДА и
соединяются через « — ». Именно по этому файлу автосвязка Г2↔Г1 понимает, что
«Магазины — Онлайн-магазины/ПВЗ» = плитка 1, подкатегория 7.

-------------------------------------------------------------------------------
4.5. id_aliases.json — СТРАХОВОЧНЫЙ ЖИЛЕТ ID
-------------------------------------------------------------------------------
Таблица «старый ID → новый ID». Нужна, чтобы «сожжённые» (уже использованные)
номера не выдавались повторно, а избранное жителей не терялось при переносе
карточки. Подмена выполняется, только если старого ключа в базе уже нет.

-------------------------------------------------------------------------------
4.6. name_synonyms.json — НАРОДНЫЕ СИНОНИМЫ ИМЁН
-------------------------------------------------------------------------------
Словарь для поиска: «Саша» находит «Александр», «Жанар» ↔ «Жанара» и т. п.
Править можно свободно, структура не ломает сайт при добавлении пар.

-------------------------------------------------------------------------------
4.7. reklama.txt — VIP-РЕКЛАМА
-------------------------------------------------------------------------------
Формат строки: «код_села | ID | ДД.ММ.ГГГГ». Пока дата не прошла, карточка
получает золото и значок «👑 VIP» и стоит первой. Вместо даты можно написать
«навсегда». Строки с «#» — комментарии.

-------------------------------------------------------------------------------
4.8. bazy_zko/<район>/baza_zko_<район>_<село>.txt — 165 БАЗ
-------------------------------------------------------------------------------
Одно село = один файл. В каждой строке ровно 20 граф через « | ». Важно для
миграции: файл идёт по возрастанию ID, секции (сотни) лежат подряд:
1101… Продукты, 1201… Кафе, …, 1701… Онлайн-магазины/ПВЗ. Перенос между
категориями физически перекладывает строку из одной сотни в другую.
Полная расшифровка граф — в файле СТРУКТУРА_БАЗЫ.txt.

-------------------------------------------------------------------------------
4.9. АВТОСВЯЗКА Г2↔Г1 (новое в v1.0.0.0)
-------------------------------------------------------------------------------
Когда вы правите строку в «Очереди заявок» → «Редактировать» и меняете название
категории в графе Г2 (и уходите из поля), сайт на лету:
  1) находит категорию в categories.json (ru или kz) → плитка C, подкатегория T1;
  2) берёт следующий свободный номер в этой сотне (с учётом базы, «сожжённых»
     ID и заявок телефона) и вписывает его в Г1;
  3) пересчитывает C и T1 в маске Г17 и обнуляет K4 в Г19 (плитка 3-го уровня
     «Прочее»);
  4) показывает в окне зелёную пометку «🔗 Г2 … → плитка …, подкатегория …;
     Г1 1107 → 1705» и пишет то же в консоль браузера (лог миграции).
Рассинхронизации быть не может: при нажатии «Применить» связка пересчитывается
ещё раз, а сервер проверяет её по-своему (link_mismatch).
Работает для NEW и для EDIT. У NEW смена ID по-прежнему проверяется на занятость.

5. АВТОМАТИКА САЙТА (JS, PWA)

-------------------------------------------------------------------------------
5.1. index.html — ВХОДНАЯ СТРАНИЦА
-------------------------------------------------------------------------------
Скелет: заголовок, шапка с плашкой «Добавить», контейнеры под экраны, подключение

5.2. script.js — СЕРДЦЕ САЙТА
-------------------------------------------------------------------------------
Всё поведение: экраны, поиск, избранное, ленивая загрузка баз, анкеты, очередь

5.3. service-worker.js — ОФЛАЙН И КЭШ
-------------------------------------------------------------------------------
Хранит копию сайта на телефоне, чтобы справочник работал без интернета.

среды удаляет сам. Стратегия «сеть сначала, кэш запасным».

5.4. manifest.webmanifest — УСТАНОВКА НА ЭКРАН ТЕЛЕФОНА
-------------------------------------------------------------------------------
Имя, иконки, цвета, версия «1.0.0.0». Благодаря ему сайт ставится как
приложение. Среду он определить не умеет — оба значения лишь указаны как
справка.

-------------------------------------------------------------------------------
5.5. validator.js — ПРОВЕРЯЛЬЩИК БАЗ И ПРЕ-ЛОНЧЕР
-------------------------------------------------------------------------------
Запускается раньше основного кода, пока крутится заставка. Проверяет строки баз
(20 граф, маски, телефоны, маркеры) и доступность config/languages/geo.
Отдаёт результат «Живому Карантину». Любая ошибка внутри него гасится и не
может обрушить запуск сайта.

-------------------------------------------------------------------------------
5.6. qr.js — ГЕНЕРАТОР QR
-------------------------------------------------------------------------------
Встроенная библиотека (MIT): рисует QR-код ссылки на сайт без интернета. Нужна
для кнопки «Поделиться».

5.7. style.css, иконки, call.html

сайта.

6. СКВОЗНЫЕ СЦЕНАРИИ: ЧТО НАЖИМАТЬ И ЧТО БУДЕТ
===============================================================================

СЦЕНАРИЙ А. Вход в пульт
  1. Запустите cartoteka_server.py в Pydroid 3 (раздел 2.1).
  2. Откройте http://localhost:1090 в Chrome.
  3. Зажмите «i» на 3 секунды. Ввод «Кода входа в админку».
  4. Что будет: откроется пульт, бейдж «🔒 Только чтение», наверху 5 кнопок.
  Если сервера нет — плашка «Запустите сервер», пульт закрыт (так задумано).

СЦЕНАРИЙ Б. Считать секреты один раз за запуск сервера
  1. «⚙️ Расширенные инженерные настройки» → нажмите плашку → введите Мастер-
     пароль (откроется «🔓 Изменения разрешены» на 10 минут).
  2. Введите путь к secrets.txt (полный, начинается с «/», вне папки проекта).
  3. Нажмите синюю «📁 СЧИТАТЬ ВСЕ КОДЫ ИЗ ФАЙЛА».
  4. Что будет: под кнопкой отметки «••••••••» у каждой найденной строки и
     «Telegram → облачный скрипт: передано ✓». Токены — только в памяти.

СЦЕНАРИЙ В. Новая заявка от жителя → на сайт
  1. Заявка пришла, в Telegram — «🆕 Новая анкета» + «💬 Комментарий».
  2. Пульт → «Очередь заявок». Нажмите на серое окошко строки — увидите полный
     разбор Г1–Г20.
  3. При опечатке: «Редактировать» → поправить → «Применить».
  4. Нажмите «Одобрить» (потребуется Мастер-пароль). Заявка уходит в облако,
     получает статус «Одобрена», строка дописывается в файл села на телефоне.
  5. Нажмите «В GitHub». Сервер читает файл, дописывает строку, отправляет.
  6. На выходе: на странице «GitHub ✔» и «Telegram ✔», в Telegram — «✅ Рапорт
     синхронизации» с коротким хешем коммита.
  7. Через несколько минут карточку видят жители.
  Затем нажмите «Внесена», когда всё закончено.

СЦЕНАРИЙ Г. Перенос карточки между категориями (пример: «Онлайн подгузники»,
ID 1107, из «Продукты» в «Онлайн-магазины/ПВЗ»)
  1. Посетитель отправил «⚠️ Ошибка» с комментарием «Перевести в онлайн
     магазины..». В Telegram придёт ровно этот текст в строке «💬 Комментарий».
  2. Очередь → заявка EDIT. Вы видите «до» и «после» (радар: красное и зелёное).
  3. «Редактировать» → в Г2 вручную впишите «Магазины — Онлайн-магазины/ПВЗ»
     (или выберите так, как в categories.json) → уйдите из поля.
  4. Что будет: Г1 сама станет, например, 1705; в Г17 поменяются плитка и
     подкатегория; зелёная строка «🔗 …» подтвердит связку. Нажмите «Применить».
  5. «Одобрить» → «В файл + Буфер»: в терминале Pydroid появится «[МИГРАЦИЯ] …
     1107 → 1705 …». Карточка исчезнет из «Продуктов» и появится в «ПВЗ».
  6. «В GitHub» — то же самое на складе. В рапорте Telegram: «перенесена запись
     (миграция 1107 → 1705 …)».
  7. Если красная ошибка: «link_mismatch» — Г1 не соответствует Г2, нажмите
     «Редактировать» и перепроверьте Г2; «idclash» — номер занят, поправьте Г1.

СЦЕНАРИЙ Д. Обновить облачный шлюз (после выхода новой версии .gs)
  1. Пульт → «Расширенные инженерные настройки» → Мастер-пароль.
  2. Нажмите кремовую кнопку «Обновить облачный шлюз таблицы».
  3. На выходе: «передано, знаков: N».
  4. Apps Script → «Начать развертывание → Управление развертываниями →
     карандаш → Версия: Новая версия → Развернуть». Адрес /exec не меняется.
  5. Проверка: откройте /exec — должно быть "version":"v1.0.0.0".

ПЕРЕД НАЧАЛОМ: распакуйте spravochnik_v1.0.0.0.zip в папку проекта на телефоне

ШАГ 2. (Необязательно, но полезно) Сначала сухой прогон. В терминале Pydroid

       Что будет: список файлов, которые уйдут. Ничего не отправляется.
ШАГ 3. Для начала выложите на ТЕСТ: нажмите ▶ у github_uploader.py, на вопрос
       введите 1 и Enter. Проверьте тестовый сайт (…/test-cartoteka/).
ШАГ 4. Затем на БОЙ: снова ▶, на вопрос введите 2 и Enter.
ШАГ 5. Дождитесь строки с коротким хешем коммита. Это и есть сигнал «готово».
ШАГ 6. Подождите 5–10 минут (кэш GitHub Pages) и откройте
       https://zko-spravochnik.github.io/cartoteka/ . Должно появиться окно
       «Обновить сейчас» (updateCritical=true) → нажмите. В шапке — надпись
       «Релиз v1.0.0.0».
ШАГ 7. Обновите шлюз Google (сценарий Д), иначе новые комментарии Telegram и
       миграция ID через облако не заработают.
ШАГ 8. Если нужно пересчитать счётчики: python build_counts.py, потом ещё раз
       ШАГ 4 (изменится config.json).
ЧЕГО НЕ ДЕЛАТЬ: не нажимайте ▶ у cartoteka_server.py и github_uploader.py
одновременно в одном окне — сервер занимает терминал. Для деплоя сервер можно
остановить (кнопка ⏹); для работы в пульте — запустить снова.

8. ЧТО ДЕЛАТЬ ПРИ ОШИБКАХ
===============================================================================
• «Запустите сервер» — не запущен cartoteka_server.py, либо сайт открыт не по
  адресу localhost:порт.
• «Неверный код» / «Подождите минуту» — Код входа не совпал; после 5 ошибок пауза
  60 секунд. Забыли — удалите .admin_auth.json и войдите заново.
• Красная ошибка Мастер-пароля — MASTER_CODE в Свойствах скрипта должен совпасть
  со строкой 2 secrets.txt; потом «Новая версия» развёртывания.
• Telegram молчит — (1) у бота не нажат /start; (2) в secrets.txt нет Token
  telegram/ID telegram; (3) не выданы права «Внешние сервисы»: в Apps Script
  выполните authorizeTelegram и дайте разрешение; (4) ADMIN_CODE в Свойствах ≠
  строке 1 файла; (5) причина видна в строке «Telegram → облачный скрипт».
• GitHub 401/403/404 — токен просрочен, нет права Contents, либо вы в тесте с
  боевым токеном (и наоборот). Смотрите метку «[ТЕСТ]» во вкладке.
• «gh_conflict» — кто-то обновил файл одновременно; нажмите кнопку ещё раз.
• Сайт не обновился на телефоне — окно «Обновить» или «Обновить данные» в пульте.
• Ошибка миграции (link_mismatch, idclash, mismatch, no_id) — раздел 2.1.
• Не видно карточки после переноса — подождите кэш (10 минут) и нажмите
  «Обновить данные».

ЧЕСТНО О ПРОВЕРКЕ: релиз проверен на имитациях (перенос строки на копии базы,
пересчёт Г1 по Г2, синтаксис всех файлов). НЕ проверялось вживую: настоящие
GitHub, Telegram и Google. Первую живую проверку выполняете вы: сначала на
тестовом сайте.
