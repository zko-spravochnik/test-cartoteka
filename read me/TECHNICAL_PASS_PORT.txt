1. ДВА РЕПОЗИТОРИЯ И ДВА КОНФИГА
--------------------------------
БОЕВОЙ     репозиторий : github.com/zko-spravochnik/cartoteka
           конфиг      : config.json
           сайт        : https://zko-spravochnik.github.io/cartoteka/
ТЕСТОВЫЙ   репозиторий : github.com/zko-spravochnik/test-cartoteka
           конфиг      : test_config.json
           сайт        : https://zko-spravochnik.github.io/test-cartoteka/

Имя репозитория в script.js НЕ прописано. Сайт сам определяет среду при
запуске (script.js, validator.js, service-worker.js):
  * тестовая среда — localhost, 127.0.0.1, любой локальный IP (192.168..,
    10.., 172.16–31..), адрес с портом (1090, 1108, 1110 и т.п.) или путь
    с «test-cartoteka» → читается test_config.json, запись (токен GitHub)
    идёт ТОЛЬКО в test-cartoteka; в заголовке вкладки метка «[ТЕСТ]»;
  * боевая среда — любой другой адрес → config.json, запись только в cartoteka.
Переключать вручную ничего не нужно. Кэши PWA у сред разные
(«cartoteka-v…» и «test-cartoteka-v…»), чтобы не стирать друг друга.
Файл manifest.webmanifest несёт оба значения (поле cartoteka_environments);
сам браузер их не читает, они — справка для людей и скриптов.
Перенос изменений из теста в бой — копированием файлов в боевой репозиторий,
при этом config.json и test_config.json остаются каждый на своём месте
(в них разные repository, repositoryUrl, qrShareUrl, intakeWebhookUrl, env).

2. КЛЮЧИ И ГДЕ ОНИ ХРАНЯТСЯ (КОНЦЕПЦИЯ v5.4.0.3)
------------------------------------------------
Принцип: ОДИН пароль на входе и ОДИН файл с кодами. Раздельных карманов ручного ввода
в пульте больше нет.

А) Единый «Код входа в админку»
   Это тот же самый пароль, что ADMIN_CODE в Свойствах скрипта Google: два имени одного
   секрета. Вводится при долгом нажатии «i» (3 секунды). В код сайта он НЕ вшит. Проверку
   делает локальный сервер (/__auth): хранится только отпечаток (PBKDF2-SHA256 с солью) в
   скрытом файле .admin_auth.json рядом с сервером. После 5 неверных попыток подряд пауза
   на минуту. Первый вход (отпечатка ещё нет) пускает в пульт, а при первом считывании
   файла код сверяется со строкой 1 файла secrets.txt, и отпечаток записывается.
   Сменить код: изменить строку 1 в secrets.txt и ADMIN_CODE в Свойствах скрипта, удалить
   файл .admin_auth.json (отпечаток создастся заново).
   Без запущенного cartoteka_server.py пульт не открывается: плашка «Запустите сервер».

Б) Файл secrets.txt (скрытый путь)
   Файл ФИЗИЧЕСКИ не лежит в папке проекта. Администратор держит его в скрытом месте
   флешки (пример пути: /storage/emulated/0/Личное!!/secrets.txt). Сервер отвергает путь
   внутри папки проекта, относительный путь, не-.txt и файлы больше 8 КБ.
   В пульте одно поле «путь к файлу» и одна синяя кнопка
   «[ 📁 СЧИТАТЬ ВСЕ КОДЫ ИЗ ФАЙЛА ]». Чистый шаблон на 14 строк лежит в папке shablony_сейф
   (внутри проекта, как образец; рабочую копию с настоящими значениями держите ВНЕ проекта).
   Структура файла и разбор — раздел 11.

В) Куда попадает каждая строка файла
   Код входа в админку      → отпечаток на сервере; совпадает с ADMIN_CODE
   Токен GitHub             → ТОЛЬКО в память страницы (и sessionStorage на время вкладки);
                              на экране «••••••••»; в config.json не пишется
   Имя репозитория GitHub   → repositoryName / repository конфига СВОЕЙ среды
                              (определяется по адресам сайтов; чужой конфиг не трогается)
   Ветка репозитория        → branch в том же конфиге
   Ссылка на сайт песочницы → qrShareUrl в test_config.json
   Ссылка на сайт боевой    → qrShareUrl в config.json
   Вебхук Google Таблицы    → intakeWebhookUrl в ОБОИХ конфигах (шлюз общий)
   Token telegram           → страница передаёт облачному скрипту (action=setTelegram с
                              ADMIN_CODE); дальше живёт в Свойствах скрипта Google
   ID telegram              → туда же (TG_CHAT_ID)
   Порт сервера             → serverPort в обоих конфигах (справка; порт запуска задаётся аргументом)
   Путь к bazy_zko          → dbRoot в обоих конфигах (если такая папка есть рядом с сервером)
   Режим Тест/Бой           → workMode («test» или «prod») в обоих конфигах (метка режима работы)
   ID Google Таблицы        → google_sync.json (для google_code_pusher.py; на GitHub не уходит)
   ПОЧЕМУ токены не «зашиваются» в config.json: config.json и test_config.json уходят на
   публичный GitHub, секрет в них стал бы публичным. В конфиги пишутся только открытые
   значения (ссылки, имя репозитория, ветка). Загрузчик github_uploader.py дополнительно
   останавливает заливку, если находит в файлах витрины шаблон токена.

Г) Telegram-бот
   Бот: @zko_cartoteka_bot (у бота один раз нажать /start). ID чата администратора берётся
   строкой «ID telegram» из secrets.txt (реальные цифры в документах не фиксируются).
   Токен и ID уходят в Свойства скрипта автоматически при считывании файла (в пульте
   строка «Telegram → облачный скрипт: передано ✓»). Нужна ссылка веб-хука: из конфига или
   из строки «Вебхук Google Таблицы» того же файла.

Д) Ссылка веб-приложения Google (…/exec)
   Публична по замыслу (секрет — ADMIN_CODE). Вид: https://script.google.com/macros/s/<ID>/exec.
   Сервер кладёт её в оба конфига, страница использует сразу. Чтобы изменение дошло до
   жителей, залейте обновлённые config.json / test_config.json загрузчиком (токены он не
   отправляет); телефоны получат конфиг примерно через 10 минут (кэш CDN GitHub Pages).

Е) Ротация
   Токен GitHub: выпустить новый, поменять строку в secrets.txt, нажать кнопку считывания,
   старый удалить. Желательно отдельные токены для боя и теста (два файла secrets, нужный
   путь вводится в поле).

3. GOOGLE APPS SCRIPT: РАЗВЁРТЫВАНИЕ
------------------------------------
Файл: google_apps_script_webhook.gs (в корне архива, на сайт не загружается).
  1. Google Таблица «Baiterek_Ochered_2026» → Расширения → Apps Script.
  2. Вставить файл целиком (заменить старый код), сохранить.
  3. Свойства скрипта: ADMIN_CODE (= Код входа в админку, он же строка 1 secrets.txt);
     TG_BOT_TOKEN и TG_CHAT_ID вручную не вносятся: их передаёт кнопка считывания файла.
  4. Развернуть → Новое развёртывание → Веб-приложение:
       Выполнять от имени : Я
       Доступ             : Все
     Скопировать ссылку, оканчивающуюся на /exec.
  5. При первом запуске Google просит разрешения: нужно разрешить доступ к
     таблице и «Внешние сервисы» (UrlFetchApp) — иначе Telegram-уведомления
     не уйдут. Если после обновления кода уведомления молчат — выполнить
     функцию вручную и повторно выдать разрешения.
  6. После КАЖДОГО изменения кода: Развернуть → Управление развёртываниями →
     изменить версию на «Новая». Адрес /exec при этом не меняется.
Проверка версии: открыть ссылку /exec в браузере — вернётся
{"ok":true,"service":"cartoteka-intake","version":"v5.4.0.4"}.
Листы очереди создаются сами: имя Район_Село (например Baiterek_Daryinskoe),
по одному на село, при первой заявке из него.

4. ЦЕПОЧКА ЗАЯВКИ
-----------------
  Телефон жителя → (ссылка /exec из конфига) → Google Таблица (лист села,
  ID +1, статус «Новая») → Telegram-бот присылает администратору сообщение
  (вид: тип карточки, село, ID, название, телефон) → админ в пульте нажимает
  «Одобрить» → сайт дописывает строку «$» в файл села в GitHub и обновляет
  счётчики села в конфиге.
Telegram-сообщение отправляется ПОСЛЕ записи в таблицу и вне блокировки:
сбой Telegram не теряет заявку.

5. ДИАГНОСТИКА
--------------
* «Запустите сервер» при удержании «i»: не запущен cartoteka_server.py или сайт открыт не
  через него. Пульт без сервера закрыт намеренно (в том числе на боевом сайте).
* «Неверный код» / «Подождите минуту»: Код входа не совпал с отпечатком; после 5 ошибок
  пауза 60 секунд. Забыли код: удалить .admin_auth.json и войти заново.
* При считывании файла: «файл лежит внутри папки проекта», «нужен полный путь» (с «/»),
  «файл не найден», «нужен файл .txt», «код в файле не совпадает с введённым кодом входа»,
  «не найдена строка Код входа в админку». Под кнопкой у каждой из 9 строк отметка
  «••••••••» или «не найдено / нет двоеточия / неверный формат значения».
* «Статистика недоступна»: неверна ссылка веб-хука (строка «Вебхук Google Таблицы»); скрипт
  не развёрнут как «Доступ: Все»; после правки кода не обновлена версия развёртывания.
* Telegram не приходит: (1) у бота не нажат /start; (2) в файле нет Token telegram / ID
  telegram или формат неверный; (3) не выданы права UrlFetchApp; (4) ADMIN_CODE в Свойствах
  скрипта ≠ строке 1 файла; (5) причину покажет строка «Telegram → облачный скрипт».
* Запись в GitHub падает (401/403/404): токен просрочен, нет права Contents, или тестовая
  среда с боевым токеном (и наоборот): проверьте метку «[ТЕСТ]» в заголовке вкладки.
* Сайт не обновился на телефоне: кэш PWA; окно «Обновить» или кнопка «Обновить данные».

6. ЛОКАЛЬНЫЙ ЗАПУСК (Pydroid 3)
-------------------------------
python cartoteka_server.py 1090 (или 1108/1110/1112) → http://localhost:порт. Среда «тестовая».
Сервер принимает только запросы с этого же телефона:
  POST /__append   дописать одобренную строку в базу села, обновить счётчики села;
  POST /__auth     проверка единого Кода входа (v5.4.0.3);
  POST /__secrets  чтение secrets.txt по введённому пути, раскладка 9 строк (v5.4.0.3);
  POST /__push_gas заливка кода шлюза в ячейку Код!A1 (раздел 10);
  GET  /__ping     «сервер жив»; пульт проверяет его перед открытием.
Служебные файлы (имя с точкой, google_service_account.json, google_sync.json) по сети не
отдаются. Пересчёт счётчиков по всем базам: python build_counts.py.

10. ЯЧЕЕЧНЫЙ МОСТ: КОД ШЛЮЗА ЖИВЁТ В ТАБЛИЦЕ (v5.4.0.1)
-----------------------------------------------------
Зачем: код google_apps_script_webhook.gs (около 28 000 знаков) не помещается в буфер
телефона. Теперь в окне Apps Script стоят только 3 коротких строки (заглушка), а сам
код лежит в ячейке A1 листа «Код» и обновляется кнопкой в админ-пульте.
Как это работает:
  заявка/команда с сайта → POST на ссылку /exec → заглушка doPost читает Код!A1 и выполняет
  текст командой eval() → выполняется настоящий doPost из файла шлюза.
Заглушка (вставляется в Apps Script ОДИН раз, весь прежний код из окна удаляется):
  function doPost(e){return eval(SpreadsheetApp.getActiveSpreadsheet().getSheetByName('Код').getRange('A1').getValue()+';doPost(e)')}
  function doGet(e){return eval(SpreadsheetApp.getActiveSpreadsheet().getSheetByName('Код').getRange('A1').getValue()+';doGet(e)')}
  function _scopes(){if(0){UrlFetchApp.fetch('');LockService.getScriptLock();PropertiesService.getScriptProperties();Utilities.formatDate(new Date(),'UTC','y');ContentService.createTextOutput('');SpreadsheetApp.getActive()}}
Третья строка нужна, чтобы Google выдал скрипту права на Внешние сервисы и т.д.: права
определяются по тексту скрипта и «не видят» код внутри eval. После вставки один раз запустить
функцию _scopes и разрешить доступ, затем выпустить новую версию развёртывания.
Если Google всё же не выдаёт права: Параметры проекта → «Показывать файл манифеста
appsscript.json» → добавить в него oauthScopes:
  https://www.googleapis.com/auth/spreadsheets, https://www.googleapis.com/auth/script.external_request,
  https://www.googleapis.com/auth/script.scriptapp (если нужен), затем выпустить новую версию.
Обновление кода шлюза: админ-пульт → жёлтая кнопка «[ 🚀 ОБНОВИТЬ ОБЛАЧНЫЙ ШЛЮЗ ТАБЛИЦЫ ]»
(с v5.4.0.3 обычная кнопка, не карман). Её обрабатывает cartoteka_server.py: он вызывает
google_code_pusher.py, тот берёт google_apps_script_webhook.gs целиком и записывает в Код!A1
через Google Sheets API (сервисный ключ, чистый Python без pip). Автономный запуск:
python google_code_pusher.py. Кнопка работает только когда сайт открыт через локальный
сервер (порт 1090/1108/1110/1112…), на боевом сайте её роль выполняет компьютер/телефон админа.
Подготовка один раз: (1) Google Cloud → проект → включить Google Sheets API; (2) создать
сервисный аккаунт и скачать ключ JSON, положить рядом с сервером под именем
[УСТАРЕЛО с v5.4.0.5: JSON-ключ больше не нужен, см. ОТЧЕТ_ВЕХИ_v5.4.0.5.txt] google_service_account.json; (3) открыть Таблицу на e-mail из поля client_email (роль «Редактор»).
ID таблицы берётся из ссылки (…/d/ID/edit), записывается в google_sync.json при первом запуске.
Безопасность: кто может править Таблицу, тот может менять выполняемый код шлюза. Не давайте
доступ посторонним. Файлы google_service_account.json и google_sync.json не загружаются на GitHub.
Лимит ячейки Таблицы — 50 000 знаков (сейчас код занимает ~28 500).
ПРАВИЛО ПОСТАВКИ: google_code_pusher.py всегда входит в ZIP-архив проекта (корень папки).

11. СТАНДАРТ secrets.txt: ВАРИАНТ 2, 13 СТРОК, РАЗДЕЛИТЕЛЬ «|» (v5.4.0.4)
------------------------------------------------------------------------
Строка = «Название | значение». Образец с заглушками: shablony_сейф/secrets.txt. 14 строк:
  Код входа в админку | <пароль>
  Токен GitHub | <ghp_… или github_pat_…>
  Имя репозитория GitHub | <test-cartoteka или cartoteka>
  Ветка репозитория | main
  Ссылка на сайт песочницы | https://zko-spravochnik.github.io/test-cartoteka/
  Ссылка на сайт боевой | https://zko-spravochnik.github.io/cartoteka/
  Вебхук Google Таблицы | <https://script.google.com/macros/s/…/exec>
  Token telegram | <123456789:AA…>
  ID telegram | <цифры>
  Порт сервера | 1112
  Путь к bazy_zko | bazy_zko
  Режим Тест/Бой | Тест
  ID Google Таблицы | <ID или ссылка на таблицу>
Почему «|», а не «:». В токене Telegram (123456789:AA…) и в ссылках (https://…) уже есть двоеточия.
Вертикальная черта в них не встречается, поэтому делить по ней надёжнее.

Алгоритм разбора (cartoteka_server.py, parse_secrets):
  1. Файл читается как UTF-8 (BOM снимается; запасной вариант cp1251).
  2. Жёсткого ограничения числа строк НЕТ: разбираются все строки файла (страховочный предел 60).
     Пустые строки и строки с «#» пропускаются. Порядок строк не важен.
  3. Каждая строка режется ОДИН раз: split('|', 1). Слева название, справа значение целиком.
  4. Название распознаётся ПО СМЫСЛУ, без привязки к номеру строки: ищутся корни «токен+github»,
     «token+telegram», «id+telegram», «вебхук», «ветк», «репозитор», «песочниц», «боев»,
     «порт», «bazy/базы», «режим/тест-бой», «id+таблиц», «код входа». Регистр и «ё» не важны,
     русские буквы-пояснения слева отбрасываются, название может быть русским или латиницей.
  5. Из значения вырезаются кавычки и лишний текст: токены, ссылки, цифры и ID берутся по шаблону.
     «Режим»: слова «тест/test» → test, «бой/боевой/prod» → prod. Порт: 1024–65535. ID таблицы:
     можно вставить всю ссылку, сервер сам вырежет ID. Код входа берётся целиком (это фраза).
  6. Неверный формат — строка отклоняется, в пульте пометка «неверный формат значения». Повтор
     названия — пометка «строка повторяется». Строка без «|» — «нет разделителя». Содержимое
     строк в сообщения не попадает.
  7. Код из строки «Код входа в админку» сверяется с введённым кодом; не совпал — ничего не применяется.
  8. Раскладка: открытое — в config.json / test_config.json (раздел 2В), ID таблицы — в
     google_sync.json, секреты (токены, ID чата) — только в память страницы и в Свойства скрипта Google.
     Под кнопкой пульта у каждой из 14 строк «••••••••» или «не найдено».

12. АВТОПИЛОТ КОММЕРЦИИ (v5.4.0.4)
----------------------------------
Словарь residentCrafts в categories.json (около 60 правил, сотни корней). Описание жителя (примечание Г5,
теги Г10, место работы Г13) проверяется по правилам сверху вниз; первое сработавшее правило задаёт
раздел: Мастера, Магазины, Такси и авто, Медицина, Госсектор или «Прочее / Прочие услуги» (широкий

в этом разделе; оригинал остаётся в «Жителях», строка в базе одна (никаких копий в файлах и конфликтов ID).
Сервер при одобрении заявки (/__append) возвращает поле craft, а /__autopilot проверяет все базы разом.
Словарь правится текстовым редактором: корни слов, «=ип» — целое слово; регистр и «ё» не важны.
