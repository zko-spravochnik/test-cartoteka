1. ДВА РЕПОЗИТОРИЯ И ДВА КОНФИГА
--------------------------------
БОЕВОЙ     репозиторий : github.com/zko-spravochnik/cartoteka
           конфиг      : config.json
           сайт        : https://zko-spravochnik.github.io/cartoteka/
ТЕСТОВЫЙ   репозиторий : github.com/zko-spravochnik/test-cartoteka
           конфиг      : test_config.json
           сайт        : https://zko-spravochnik.github.io/test-cartoteka/

Имя репозитория в script.js НЕ прописано. Сайт сам определяет среду при
запуске (script.js, validator.js, service-worker.js):
  * тестовая среда — localhost, 127.0.0.1, любой локальный IP (192.168..,
    10.., 172.16–31..), адрес с портом (1090, 1108, 1110 и т.п.) или путь
    с «test-cartoteka» → читается test_config.json, запись (токен GitHub)
    идёт ТОЛЬКО в test-cartoteka; в заголовке вкладки метка «[ТЕСТ]»;
  * боевая среда — любой другой адрес → config.json, запись только в cartoteka.
Переключать вручную ничего не нужно. Кэши PWA у сред разные
(«cartoteka-v…» и «test-cartoteka-v…»), чтобы не стирать друг друга.
Файл manifest.webmanifest несёт оба значения (поле cartoteka_environments);
сам браузер их не читает, они — справка для людей и скриптов.
Перенос изменений из теста в бой — копированием файлов в боевой репозиторий,
при этом config.json и test_config.json остаются каждый на своём месте
(в них разные repository, repositoryUrl, qrShareUrl, intakeWebhookUrl, env).

2. КЛЮЧИ И ГДЕ ОНИ ХРАНЯТСЯ
---------------------------
А) Токен GitHub (ghp_…, право записи Contents на нужный репозиторий)
   Где вводится : сайт → долгое нажатие «i» → админ-пульт → карман
                  «Токен GitHub». Хранится в браузере администратора.
   Для чего     : одобрение заявок (дописать строку в базу села), запись
                  config.json / test_config.json (ссылка веб-хука, QR,
                  счётчики сёл), резервные копии.
   Ротация      : GitHub → Settings → Developer settings → Tokens: выпустить
                  новый, ввести в карман, старый удалить. Отдельный токен
                  для боя и для теста — желательно.

Б) ADMIN_CODE (секрет админа для Google-скрипта)
   Где хранится : Google Apps Script → Настройки проекта → Свойства скрипта.
   Где вводится : админ-пульт → карман «Код администратора».
   Нужен для    : чтения очереди, смены статусов, пересчёта ID, настройки и
                  теста Telegram. Гости умеют только ДОБАВЛЯТЬ заявки.

В) Telegram-бот
   Бот          : @zko_cartoteka_bot (у бота нужно один раз нажать /start)
   Chat ID админа: 8993374736
   Токен бота (TG_BOT_TOKEN) и Chat ID (TG_CHAT_ID) лежат в Свойствах скрипта
   Google и в браузере НЕ хранятся. Вводятся в админ-пульте, карман
   «Telegram», поля telegramBotToken и telegramChatId → кнопка записи
   (сайт передаёт их скрипту с ADMIN_CODE) → кнопка «Тест».

Г) Ссылка веб-приложения Google (…/exec)
   Публична по замыслу (секрет — ADMIN_CODE, а не ссылка).
   Где вводится : админ-пульт → карман «Веб-хук» (поле ссылки). Сайт сам
                  записывает её в активный конфиг (поле intakeWebhookUrl;
                  в боевой или тестовый — по среде) через GitHub.
   Проверка     : после записи сайт сам запрашивает статистику; ссылка должна
                  иметь вид https://script.google.com/macros/s/<ID>/exec.
   Задержка     : телефоны получают новый конфиг примерно через 10 минут
                  (кэш CDN GitHub Pages); можно ускорить кнопкой
                  «Обновить данные».

3. GOOGLE APPS SCRIPT: РАЗВЁРТЫВАНИЕ
------------------------------------
Файл: google_apps_script_webhook.gs (в корне архива, на сайт не загружается).
  1. Google Таблица «Baiterek_Ochered_2026» → Расширения → Apps Script.
  2. Вставить файл целиком (заменить старый код), сохранить.
  3. Свойства скрипта: ADMIN_CODE (придумать), TG_BOT_TOKEN, TG_CHAT_ID —
     последние два можно не вносить вручную, а задать из админ-пульта.
  4. Развернуть → Новое развёртывание → Веб-приложение:
       Выполнять от имени : Я
       Доступ             : Все
     Скопировать ссылку, оканчивающуюся на /exec.
  5. При первом запуске Google просит разрешения: нужно разрешить доступ к
     таблице и «Внешние сервисы» (UrlFetchApp) — иначе Telegram-уведомления
     не уйдут. Если после обновления кода уведомления молчат — выполнить
     функцию вручную и повторно выдать разрешения.
  6. После КАЖДОГО изменения кода: Развернуть → Управление развёртываниями →
     изменить версию на «Новая». Адрес /exec при этом не меняется.
Проверка версии: открыть ссылку /exec в браузере — вернётся
{"ok":true,"service":"cartoteka-intake","version":"v5.4.0.0"}.
Листы очереди создаются сами: имя Район_Село (например Baiterek_Daryinskoe),
по одному на село, при первой заявке из него.

4. ЦЕПОЧКА ЗАЯВКИ
-----------------
  Телефон жителя → (ссылка /exec из конфига) → Google Таблица (лист села,
  ID +1, статус «Новая») → Telegram-бот присылает администратору сообщение
  (вид: тип карточки, село, ID, название, телефон) → админ в пульте нажимает
  «Одобрить» → сайт дописывает строку «$» в файл села в GitHub и обновляет
  счётчики села в конфиге.
Telegram-сообщение отправляется ПОСЛЕ записи в таблицу и вне блокировки:
сбой Telegram не теряет заявку.

5. ДИАГНОСТИКА
--------------
* «Статистика недоступна» / «нет связи с таблицей»: пуста или неверна ссылка
  веб-хука в активном конфиге; скрипт не развёрнут как «Доступ: Все»; после
  правки кода не обновлена версия развёртывания.
* Telegram не приходит: (1) у бота не нажат /start; (2) не заданы TG_BOT_TOKEN
  / TG_CHAT_ID (кнопка статуса в кармане покажет «настроено / нет»); (3) не
  выданы права UrlFetchApp; (4) неверный ADMIN_CODE; (5) кнопка «Тест» —
  вернёт текст ошибки Telegram.
* Запись в GitHub падает (401/403/404): токен просрочен, нет права Contents,
  или вы в тестовой среде с боевым токеном (и наоборот) — репозиторий выбирается
  средой, проверьте метку «[ТЕСТ]» в заголовке вкладки.
* Сайт не обновился на телефоне: кэш PWA; окно «Обновить» или кнопка
  «Обновить данные» в пульте.
* Переезд со старого адреса (test-cartoteka как боевой): жителям нужно открыть
  новый адрес и заново установить PWA.

6. ЛОКАЛЬНЫЙ ЗАПУСК (Pydroid 3)
-------------------------------
python cartoteka_server.py 1090 (или 1108/1110) → открыть http://localhost:порт
Среда автоматически «тестовая». Сервер принимает /__append (дописать строку
в базу на телефоне) и обновляет счётчики села в test_config.json.
Пересчитать счётчики по всем базам: python build_counts.py (в корне проекта).
