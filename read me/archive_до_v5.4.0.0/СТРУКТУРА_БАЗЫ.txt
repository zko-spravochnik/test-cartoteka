Пошаговая расшифровка назначения всех 20 граф строки базы
===============================================================================

Каждая строка файлов baza_zko_baiterek_*.txt — РОВНО 20 граф, разделённых
последовательностью « | » (пробел, вертикальная черта, пробел), то есть
19 разделителей. Порядок граф менять и сдвигать НЕЛЬЗЯ. Пустое значение
записывается одной точкой «.». Строки, начинающиеся с «#», — комментарии.

Г1  — ID. Абсолютный номер записи. Положение карточки на сайте вычисляется из
      него математикой: супер-плитка = целая часть ID/1000, под-плитка =
      целая часть ID/100 по модулю 10. Диапазоны: 0–999 — системный резерв
      (экстренные службы), 1000–9999 — бизнес (9×9 плиток, до 99 записей в
      «сотне»), 10000 и выше — ЖИТЕЛИ (единый ряд, первый авто-ID 10001).
      Новый ID выдаёт Google Таблица по каскаду +1 внутри своей «сотни»
      (жители — единый ряд), под блокировкой от одновременных заявок.
Г2  — Папка. Для бизнеса — живой текст «Главная — Подкатегория» из
      categories.json; для жителей — служебное слово «ЖИТЕЛИ».
Г3  — Главный заголовок: название организации или ФИО жителя. По нему строится
      алфавитная сортировка внутри «сотни».
Г4  — Владелец (ФИО владельца для бизнеса; «.» для жителей).
Г5  — Примечание жителя (девичья фамилия/должность; «.» для бизнеса).
      Г4 и Г5 — зеркальная пара: заполняется строго одна из двух.
Г6  — [ Город ] Стационарный городской телефон (только цифры). Идёт ПЕРВЫМ в
      блоке связи карточки. Если вписан короткий номер (до 7 цифр), код
      района села (например, 71130) дописывается автоматически. Напротив Г6
      кнопки WhatsApp НЕТ — доступна только кнопка «Позвонить».
Г7  — [ Mobile #1 ] Главный сотовый номер в формате +7XXXXXXXXXX. Кнопки
      «Позвонить» и WhatsApp стоят в ряд (WhatsApp — только если подтверждён
      флагом в Г17/Г18).
Г8  — [ Mobile #2 ] Второстепенный сотовый номер, тот же формат и правила.
Г9  — Адрес (улица, дом).
Г10 — Поисковые теги-синонимы (свободный текст). Коды сёл в Г10 обычно НЕ
      хранятся; код села берётся из геоданных. Если в тегах встретится
      отдельное 5-значное число, совпадающее с известным кодом села/района,
      оно используется при стирании Г6 в окне «Ошибка».
Г11 — География: «с. <Название села>».
Г12 — График работы: текст либо код цикличной смены SHIFT|работа|отдых|ДАТА|ЧЧ:ММ.
Г13 — Социальная метка / место работы.
Г14, Г15, Г16 — служебный резерв: всегда буква «R». Любое другое значение —
      структурная ошибка.
Г17 — [HOME LOCK] маска бизнеса. Формат X/C/T1/T2/G/L/W1/W2/0/0:
      X — индекс села (1–5, совпадает с индексом файла), C — супер-плитка 1–9,
      T1 — под-плитка 1–9, T2 — активный тег 0–4, G — график (1 обычный,
      2 круглосуточно, 3 по звонку, 4 сменный), L — есть городской (0/1),
      W1 / W2 — WhatsApp подтверждён на Mobile #1 / #2 (0/1), 0/0 — хвост.
      У жителей Г17 всегда «0».
Г18 — [RESIDENT LOCK] маска жителя. Формат X/P/L/M1/M2/0/0:
      X — индекс села, P — буква «P» (признак жителя), L — есть городской,
      M1 / M2 — WhatsApp на Mobile #1 / #2, 0/0 — хвост. У бизнеса Г18 = «0».
Г19 — [SEARCH LOCK] маска поиска. Формат X/K1/K2/K3/K4/0/0:
      K1 — есть сотовый, K2 — тип (1 бизнес, 2 житель), K3 — есть WhatsApp,
      K4 — копия тега T2. Заполняется всегда, по ней работает глубокий поиск.
Г20 — Знак завершения / маркер модерации:
      «$» — проверено, видно посетителям;
      «NEW» — новая заявка, ещё не внесена; «ORIGINAL» + «EDIT» — пара строк
      заявки на исправление (до и после); «DELETE_1..4» / «DELETE_<текст>» —
      заявка на удаление с причиной. Все маркеры, кроме «$», уводят строку в
      «Живой Карантин» (виден только администратору).

КАК СТРОКА ПОПАДАЕТ В БАЗУ (v5.3.0.2)
  1. Посетитель отправляет анкету: она ложится в очередь телефона (IndexedDB)
     и уходит в Google Таблицу на лист своего села (Baiterek_Daryinskoe и
     др.). При обрыве связи (таймаут 7 секунд) заявка ждёт и досылается сама.
  2. Таблица присваивает ID +1 и статус «Новая».
  3. На пульте «Очередь заявок» администратор нажимает «Одобрить» → «Копировать»
     (строка с маркером «$») либо «В файл на телефон» (через
     cartoteka_server.py) и «В GitHub» → «Внесена».
  Правки и удаления вносятся вручную.

v5.3.0.2 — ПЛИТКИ 3-ГО УРОВНЯ И T2 ДО 9 (дополнение к структуре базы)
=====================================================================
Г17 (HOME LOCK): X/C/T1/T2/G/L/W1/W2/0/0. T2 теперь 0–9 (раньше 0–4) и означает
НОМЕР ПЛИТКИ 3-го уровня внутри подкатегории C/T1. Г19: X/K1/K2/K3/K4/0/0, где
K4 = точная копия T2 (диапазон тоже 0–9). T2=0 — «без плитки»: карточка попадает
в автоплитку «Прочее» (показывается, только если в ней есть карточки).
Названия плиток НЕ зашиты в код: они в categories.json (ключ tiles у подкатегории,
поля t2/ru/kz/emoji/hidden; порядок на экране = порядок в массиве). Подкатегория
без tiles (null) показывает карточки списком, как раньше.
ID по-прежнему 4 цифры: 1-я = супер-плитка, 2-я = подкатегория (сотня), 2 последние
= номер в сотне. Плитка (T2) на ID не влияет — перенос между плитками = правка T2
в Г17 и Г19 (K4), ID не меняется. Перенос между ПОДКАТЕГОРИЯМИ = смена ID.
Г2 всегда строится как «Супер — Подкатегория» (русские названия из categories.json).
Новые подкатегории: Магазины/7 «Онлайн-магазины/ПВЗ»; Прочее/3 «Культура/Религия»
(вместо «Фото/Печать»); Прочее/7 «Помощь: оформление документов ЕНПФ/ЦОН».
Правила K-полей Г19 для коммерции: K1=1 если есть сотовый, K2=1, K3=1 если есть
подтверждённый WhatsApp (W1 или W2), K4=T2.
