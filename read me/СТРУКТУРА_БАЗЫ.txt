1. ГДЕ ЛЕЖАТ БАЗЫ
-----------------
Одно село = один текстовый файл. Всего 165 файлов (Бәйтерек 29, остальные
11 районов области — 135 сёл, Уральск 1).

  bazy_zko/<папка-района>/baza_zko_<папка-района>_<село>.txt

Примеры:
  bazy_zko/baiterek/baza_zko_baiterek_daryinskoe.txt
  bazy_zko/burlinsky/baza_zko_burlinsky_aksay.txt

Папки районов (13): baiterek, akzhaiksky, bokeyordinsky, burlinsky,
zhangalinsky, zhanibeksky, karatobinsky, kaztalovsky, syrymsky, taskalinsky,
terektinsky, chingirlausky, uralsk.

Точный путь каждого файла записан в config.json (и в test_config.json):
villages[].path. Если поля path нет, путь собирается из имени файла и поля
dbRoot («bazy_zko»). Сайт НЕ скачивает все файлы сразу: при старте берётся
только база выбранного села (ленивая загрузка), остальные — когда житель
открывает село.

Новое село = (1) пустой файл по маске имени, (2) строка в villages[] и files[]
обоих конфигов, (3) строка в kazakhstan_geo.json (с dbPath).

2. ОБЩИЕ ПРАВИЛА СТРОКИ
-----------------------
* Ровно 20 граф, разделитель — « | » (пробел, вертикальная черта, пробел),
  то есть 19 разделителей. Порядок граф менять и сдвигать нельзя.
* Пустое значение — одна точка «.» (авто-точка). Пробелов-пустышек нет.
* Строки, начинающиеся с «#», — комментарии (сайт их пропускает).
* Кодировка UTF-8, перенос строки обычный; сайт читает файл как текст.

3. ГРАФЫ
--------
Г1  — ID записи (см. раздел 4).
Г2  — Папка. Бизнес: «Главная — Подкатегория» (живой текст из categories.json).
      Жители: служебное слово «ЖИТЕЛИ».
Г3  — Главный заголовок: название организации или ФИО жителя. По нему строится
      алфавитная сортировка внутри «сотни».
Г4  — Владелец (для бизнеса; у жителей «.»).
Г5  — Примечание жителя (девичья фамилия, должность; у бизнеса «.»).
      Г4 и Г5 — зеркальная пара: заполняется строго одна из двух.
Г6  — Городской телефон, только цифры. Первым в блоке связи. Короткий номер
      (до 7 цифр) получает код АТС района автоматически (код берётся из
      kazakhstan_geo.json по связке село→район). Кнопки WhatsApp у городского
      номера нет — только «Позвонить».
Г7  — Mobile #1, формат +7XXXXXXXXXX (без пробелов, скобок и лишних префиксов
      8, +8, 007). Кнопки «Позвонить» и WhatsApp (WhatsApp — только если
      подтверждён флагом в Г17/Г18).
Г8  — Mobile #2, тот же формат и правила.
Г9  — Адрес (улица, дом).
Г10 — Теги-синонимы для поиска (свободный текст).
Г11 — География: «с. <Официальное название села>».
Г12 — График работы: текст либо код сменного графика
      SHIFT|работа|отдых|ДАТА|ЧЧ:ММ.
Г13 — Социальная метка / место работы.
Г14, Г15, Г16 — служебный резерв: всегда буква «R». Иное значение — ошибка.
Г17 — [HOME LOCK] маска бизнеса: X/C/T1/T2/G/L/W1/W2/0/0
        X  — индекс села (число 1–165 из config.json, уникально в области)
        C  — супер-плитка 1–9
        T1 — подкатегория 1–9
        T2 — номер плитки 3-го уровня 0–9 (0 = «Прочее»)
        G  — график: 1 обычный, 2 круглосуточно, 3 по звонку, 4 сменный
        L  — есть городской телефон (0/1)
        W1/W2 — WhatsApp подтверждён на Mobile #1 / #2 (0/1)
        0/0 — хвост
      У жителей Г17 всегда «0».
Г18 — [RESIDENT LOCK] маска жителя: X/P/L/M1/M2/0/0
        X — индекс села, P — буква «P», L — городской, M1/M2 — WhatsApp,
        0/0 — хвост. У бизнеса Г18 = «0».
Г19 — [SEARCH LOCK] маска поиска: X/K1/K2/K3/K4/0/0
        K1 — есть сотовый, K2 — тип (1 бизнес, 2 житель), K3 — есть
        подтверждённый WhatsApp, K4 — точная копия T2 из Г17.
Г20 — Маркер: «$» — проверено, видно посетителям.
      Все остальные уводят строку в «Живой карантин» (виден только админу):
        NEW — новая заявка;
        ORIGINAL + EDIT — пара строк заявки на исправление (до и после);
        DELETE_1 … DELETE_4 / DELETE_<текст> — заявка на удаление с причиной.

4. ПРАВИЛА ID (Г1)
------------------
* Бизнес: ID = супер-плитка×1000 + подкатегория×100 + номер в сотне.
  Пример: 1101 — Магазины (1), подкатегория 1, запись 01.
  Диапазон бизнеса 1000–9999; в «сотне» до 99 записей.
* Экстренные службы: 0–999 (системный резерв).
* Жители: единый ряд от 10001 и выше.
* Изоляция по файлу: нумерация ведётся строго внутри файла своего села.
  В Байконысе и в Дарьинском бизнес независимо начинается с ...01.
* Перенос карточки между плитками 3-го уровня = правка T2 (Г17) и K4 (Г19),
  ID не меняется. Перенос между подкатегориями = смена ID.
* Новый ID выдаёт Google Таблица под блокировкой (+1 внутри «сотни»),
  не пересекаясь с занятыми.

5. ПРО ПРЕФИКСЫ В ТЕЛЕФОНАХ
---------------------------
Мобильный записывается только как +7XXXXXXXXXX. Лишние «8», «+8», «007»,
пробелы и тире сломают проверку, поиск и кнопки WhatsApp. Городской — только
цифры; код района добавляется системой. Перед анкетой сайт показывает
окно-инструкцию с этим правилом.

6. СЧЁТЧИКИ СЁЛ [бизнес][жители] (v5.4.0.0)
-------------------------------------------
Первое число — карточки коммерции (Г2 ≠ «ЖИТЕЛИ»), второе — жители
(Г2 = «ЖИТЕЛИ»). Не считаются комментарии, строки не из 20 граф и строки с
маркерами карантина (всё, кроме «$»). Незагруженные села берутся из лёгкого
индекса counts в config.json / test_config.json, загруженное село считается
вживую по тексту базы. Индекс обновляется: (а) при одобрении заявки админом
(сайт дописывает counts в активный конфиг), (б) локальным сервером при записи
строки, (в) скриптом build_counts.py (полный пересчёт по всем файлам).
Сёла с [0][0] на экране района сворачиваются в нижний карман
«[ + Показать остальные сёла... ]».

7. КАК СТРОКА ПОПАДАЕТ В БАЗУ
-----------------------------
  1. Посетитель заполняет анкету → заявка уходит в Google Таблицу на лист
     своего села (Район_Село), при обрыве связи ждёт в очереди телефона.
  2. Таблица присваивает ID и статус «Новая», Telegram-бот присылает
     уведомление админу.
  3. В пульте «Очередь заявок» админ нажимает «Одобрить» → строка с маркером
     «$» дописывается в файл села (GitHub активной среды: боевой
     zko-spravochnik/cartoteka или тестовый zko-spravochnik/test-cartoteka).
  Правки и удаления внутри существующих строк вносятся вручную.

8. РЕКЛАМА (VIP)
----------------
reklama.txt: строки «код_села | ID | ДД.ММ.ГГГГ». Пока дата не прошла,
карточка получает тег рекламы: золотой фон, корона, место первой в категории.
